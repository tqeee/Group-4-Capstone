## Architecture

- **Schema** `prisma/schema.prisma`: Investor (5.1), Fund, FundFlow (5.2), Deal (5.4 MT5 subset), ImportBatch, FundDailyNav + InvestorDailyLedger (§8.1 daily workings — 5.3 holdings are DERIVED from ledger closing share %), AuditLog, PortalSetting. Migration `init` applied. Client generated to `generated/prisma` (import `@/generated/prisma/client`); regenerate with `npx prisma generate`, migrate with `npx prisma migrate dev` (prisma.config.ts uses DIRECT_URL for CLI, DATABASE_URL for runtime).
- **Core libs**: `lib/db.ts` (Prisma singleton + PrismaPg adapter), `lib/ledger.ts` (§8.1 `rebuildFundLedger` — replays days: P&L pro-rata by opening share → apply processed flows → recompute share %; §8.2 `compoundReturn`), `lib/queries.ts` (ALL page read models; Decimal→number; ISO strings), `lib/audit.ts` (safe audit writer), `lib/email.ts` (Resend), `lib/settings.ts` (PortalSetting KV, defaults; minDeposit/minWithdrawal enforced on submission), `lib/format.ts` (fmtDate/fmtMonth/fmtMoney/fmtPct), `lib/auth/guards.ts` (`requireRole()` for server actions), `lib/auth/roles.ts` (lowercase Supabase roles; DB enum is UPPERCASE — map via `DB_ROLE` in users/actions.ts).
- **Flow lifecycle**: PENDING → (ops approve → APPROVED + processedDate + ledger rebuild → COMPLETED) or REJECTED. Ledger rebuild marks APPROVED→COMPLETED.
- **MFA**: login action redirects to `/mfa` when the `getUser()`-authenticated user has a verified factor (password sign-in is AAL1); proxy (`lib/supabase/proxy.ts`) blocks all but `/mfa` until the verified `aal` claim is `aal2`; `/mfa/setup` enrolls/unenrolls (QR + secret). MFA client events audited via `app/(auth)/mfa/actions.ts`. NEVER call `mfa.getAuthenticatorAssuranceLevel()` server-side — it reads `session.user` from cookie storage and triggers the supabase-js "could be insecure" warning; derive the state from `getUser().user.factors` + `getClaims().claims.aal` instead.
- **Auth data rule**: authorization decisions server-side use `supabase.auth.getUser()` (Auth-server-verified; proxy does this per request, so deleted users drop immediately) or `getClaims()` (signature-verified JWT; used in layouts/actions where a network hop per render is overkill). Never read the user off a stored session.
- **Ingestion** (§3.2): `app/(operations)/data-import/actions.ts` — CSV → papaparse → validate → `deal.createMany skipDuplicates` (idempotent by ticket) → ImportBatch record → ledger rebuild. Accepts BOTH broker formats: numeric dataset-5.4 codes AND the firm's real workbook format (`sample data portal.xlsm`, sheet "5.4 Dummy Data"): string `type`/`entry` ('buy'/'sell'/'balance', 'IN'/'OUT' — mapped via DEAL_TYPES/ENTRY_TYPES), `time` as Excel serial days (46098.23… → epoch offset 25569) with `time_msc` (unix ms) preferred when present, unnamed leading index column tolerated. `type=balance` rows (broker deposits/withdrawals) are EXCLUDED from import with a message telling ops to record them as fund flows; `rebuildFundLedger` also filters `type != 2` defensively. Samples: `public/sample-data/sample-data-portal.csv` (faithful conversion of the firm workbook: 564 trades + 1 balance row, 17 Mar–8 Apr 2026, total P&L −16,028.12 — verified to the cent against the source) and `broker-deals-2026-04-09.csv` (old numeric format, adds one day, net +606.95).
- **Statements**: `app/api/statements/[month]/route.ts` generates CSV from ledger for the signed-in investor; Documents page lists real months.

## Gotchas

- Prisma Decimal is not client-serializable — always `Number()` in lib/queries.ts.
- Ledger day semantics: flows processed on day D apply at END of day D (per §8.1); seed processes Faye's deposit 16 Mar so trading starts 17 Mar with capital. P&L on a day with zero opening balance is recorded on the fund but unattributed to investors.
- `useActionState` + modal close: use the render-time "adjust state during render" pattern (see UsersClient/RequestTransactionClient), NOT setState in useEffect — the lint errors on it.
- Server actions POST through the proxy; MFA challenge/enroll runs browser↔Supabase directly (only audit goes through the server).
- Windows: case-only renames need two-step `git mv`; `npx tsc` caches via tsconfig.tsbuildinfo (delete if stale).
- Seed reads `.env` via dotenv (NOT `.env.local`) — keep the two files in sync (see env gotcha above).
- All work is uncommitted on branch `yinuo` (plus earlier refactor changes). Nothing has been committed or pushed.
